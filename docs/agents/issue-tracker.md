# Issue tracker: GitHub

Issues and specs live in GitHub Issues in nllptr/tutor.
Publish specs as issues with the ready-for-agent label.

Prefer the GitHub connector. Use gh when CLI access works.
Verify the repository before writing; never file Tutor issues upstream.
For multiline CLI bodies, use a UTF-8 file and --body-file.

Read issues and comments before acting. Apply labels additively.
Record results and remaining limitations before closing issues.
Use native sub-issues and blocking dependencies when available;
otherwise record relationships in issue bodies.

PRs as a request surface: no.
